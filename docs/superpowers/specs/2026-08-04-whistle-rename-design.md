# weasel → whistle rename — design

**Date:** 2026-08-04
**Status:** approved (design), pending implementation
**Context:** `weasel` (NixOS-WSL work distro, cut over 2026-07-22, sole distro since
Debian was unregistered 2026-08-04) gets renamed to `whistle`. Scott's call, purely a
naming preference — no functional change is intended anywhere. The rename is
"all layers": repo, live Linux identity, tailnet, syncthing labels, peer configs, and
the WSL distro registration on the Windows side.

## Problem

`weasel` is baked into four independent layers, each needing its own touch:

1. **dotfiles repo** — `hosts/weasel/`, the `nixosConfigurations.weasel` flake key, the
   agenix recipient binding in `secrets/secrets.nix`, 5 incidental strings/comments in
   `ioshi/`, the `docs/ioshi/weasel.md` runbook (59 refs), and 6 dated spec/plan docs
   (178 refs).
2. **live Linux identity** — `wsl.conf` `hostname=weasel` (nix-managed via
   `wsl.wslConf`, *not* `networking.hostName`), the tailnet machine name
   (`weasel`, 100.64.0.10), the syncthing self device label.
3. **peers** — eminix's hand-written `~/.ssh/config` `Host weasel` block (never was
   nix-managed), datacore's syncthing peer label for this node.
4. **Windows** — the WSL distro registration name. WSL has no rename command; the
   options are a registry edit or an export/import. Plus a Windows Terminal
   `defaultProfile` GUID that is derived from the distro name.

## Non-goals

- No re-keying of agenix secrets. The host SSH key is not regenerated by a rename, so
  key material is unchanged and every `.age` file still decrypts. The literal
  `root@weasel` comment inside the pubkey string in `secrets/secrets.nix` stays
  verbatim — it is the real comment on the still-current key, and editing it would make
  the file lie.
- No export/import of the distro (~65 GB of churn on a 512 GB laptop for a cosmetic
  gain). Registry edit only.
- No change to ports (sshd 2222, syncthing 8385/22001), the tailnet IP
  (100.64.0.10), syncthing device IDs, or the three-node topology.
- No rewriting of dated historical specs/plans (see §1.4).
- The duplicate tailnet node records (`eminix` offline 22h + `eminix-mzbvi6by` online)
  are pre-existing cruft, noticed while scoping. Out of scope.

## Design

### 1. Repo (Phase 1 — reversible, one commit, nothing disrupted)

**1.1 Host directory and flake**

- `git mv hosts/weasel hosts/whistle`
- `flake.nix`: the `weasel = nixpkgs.lib.nixosSystem` attribute → `whistle`, the
  `./hosts/weasel/configuration.nix` import path, and the 2 prose comments (lines ~71,
  ~169).
- `hosts/whistle/configuration.nix`: header comment, `wsl.wslConf.network.hostname =
  "whistle"`, the 2 retirement/history comments, the `docs/ioshi/weasel.md` pointer.
- Also set `system.name = "whistle"` here. The generation label currently reads
  "unnamed" because `networking.hostName` is deliberately `""`; this is the known fix
  and the rename is the natural moment to land it.

**1.2 Secrets**

`secrets/secrets.nix`: rename the recipient binding `weasel` → `whistle` and update its
use in `"openrouter-auth.age".publicKeys`. Key string untouched (see Non-goals).

**1.3 Incidental strings**

`ioshi/i-intelligence/standalone.nix`, `ghostty.nix`, `packages.nix`,
`emacs/lisp/scott-launcher.el` (comments), and `zsh.nix` line ~76 — the last is a
**user-facing** message printing `wsl --terminate weasel`, so it must be correct, not
just tidy.

**1.4 Docs**

- `git mv docs/ioshi/weasel.md docs/ioshi/whistle.md` and rewrite all 59 refs. This is
  the operational runbook — the one doc that must describe the machine as it is now.
- `docs/ioshi/standalone-hm.md`: 1 ref.
- `docs/superpowers/specs/` + `plans/` (6 files, 178 refs): **filenames and prose stay
  as written.** They are dated records of work performed under the name weasel;
  rewriting them would make July's design docs claim a name that did not exist yet. The
  4 weasel-titled ones — the `2026-07-21-weasel-nixos-wsl` spec+plan and the
  `2026-07-23-weasel-zellij-zellaude` spec+plan — each get a one-line note under their
  header (the two `ewm-winit-backend` docs only mention weasel in passing and need
  nothing):
  `> weasel was renamed to whistle on 2026-08-04 — see 2026-08-04-whistle-rename-design.md.`

**1.5 Build proof before committing**

`nix build .#nixosConfigurations.whistle.config.system.build.toplevel` must succeed, and
the delta against the running system must be only `/etc/wsl.conf` and the generation
name. Then commit and push (GitHub → datacore mirror, per the flake-only workflow).

### 2. Activate on this box (Phase 2 — still non-disruptive)

- Build as `scott`, activate as root — `nix-env -p /nix/var/nix/profiles/system --set
  <path>` then `switch-to-configuration switch`. Plain `sudo nixos-rebuild` still fails
  on libgit2 repo ownership.
- After activation `/etc/wsl.conf` says `hostname=whistle`, but the **live hostname
  stays `weasel` until WSL restarts** — `wsl.conf` is read at distro start. This gap is
  harmless and expected; do not chase it.
- `tailscale set --hostname=whistle`. This renames the existing node (same node key, IP
  stable) rather than creating a second one, and persists in prefs across restarts.
  MagicDNS `weasel` stops resolving at this moment — which is what makes §3 urgent.
- Syncthing self label: rename via the local API/GUI. `overrideDevices = true` manages
  only the *peer* list declaratively; the self label came from the hostname at first
  start and will not follow a hostname change on its own. Device ID is unchanged, so no
  re-pairing.

### 3. Peers (Phase 3)

- **eminix** (reachable at 100.64.0.11; the `eminix` MagicDNS name currently points at
  the stale offline record): `~/.ssh/config` `Host weasel` → `Host whistle`. The block
  has `Port 2222` and `StrictHostKeyChecking accept-new` and relies on DNS resolving the
  bare name, so it breaks the moment §2's tailscale rename lands. Still a plain
  hand-written file; if eminix's ssh config ever moves into the flake, carry this over.
  The stale `weasel` entry in eminix's `known_hosts` is harmless (same host key,
  `accept-new` re-learns under the new name).
- **datacore**: syncthing peer label for this node, imperative there. Cosmetic — the
  device ID is what the folders bind to.

### 4. Windows (Phase 4 — disruptive; Scott runs this, last)

`wsl --shutdown` terminates the distro this session lives in, so every preceding phase
must be committed, pushed, and verified first. From PowerShell:

```powershell
wsl --shutdown
$k = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss\{ef72914c-2122-46d0-9b1f-800c91cf0d9f}'
Rename-Item "$env:LOCALAPPDATA\wsl\weasel" whistle
Set-ItemProperty $k DistributionName whistle
Set-ItemProperty $k BasePath "$env:LOCALAPPDATA\wsl\whistle"
wsl -l -v
```

The directory rename is a same-volume move (instant, no data copied) and holds the
`ext4.vhdx`. Both registry values must change together — `BasePath` still pointing at
`...\wsl\weasel` after the folder move is the one way to make the distro unstartable.

**Rollback:** the same three edits in reverse, while shut down.

**Windows Terminal — the one real footgun.** WT derives WSL dynamic-profile GUIDs from
the distro *name*. `defaultProfile` is currently pinned to `{9615d19c-43da-5f57-b75a-7d1a947760f9}`,
the weasel-derived GUID. After the rename WT generates a **new** profile named `whistle`
with a different GUID, and `defaultProfile` points at a profile that no longer exists.
Fix, in order: launch WT once so the new profile generates, repoint `defaultProfile` to
its GUID, then delete the orphaned `weasel` entry — and the stale `Debian` entry still
sitting in `profiles.list` from the unregistered distro.

`~/.glzr/glazewm/config.yaml` mentions weasel in 2 comments about the WT default
profile. Cosmetic, but they are the comments that explain the keybind, so update them.

### 5. Verification (Phase 5)

Every check below is a command with an expected output, run after the Phase 4 restart:

| Check | Expectation |
|---|---|
| `hostname` / `cat /etc/hostname` | `whistle` |
| `grep hostname /etc/wsl.conf` | `hostname=whistle` |
| `wsl -l -v` (PowerShell) | one distro, `whistle`, Running, v2 |
| `tailscale status --self` | name `whistle`, IP still 100.64.0.10 |
| `systemctl --user is-active syncthing` + peer state | active; datacore connected, labels updated both ends |
| `ssh whistle` from eminix | lands on `whistle`, port 2222 |
| `systemctl --user is-system-running`, `sudo -n true` | user session healthy (the `wsl-user-session-rescue` path), passwordless wheel intact |
| `nixos-rebuild list-generations` (or profile label) | reads `whistle`, no longer "unnamed" |
| WSLInterop | `/mnt/c/Windows/System32/cmd.exe /c echo ok` works — the distro's own boot re-registers it |
| WT | default profile opens whistle; no orphan `weasel`/`Debian` entries |

Then update the Claude memory files: `project_weasel.md` → `project_whistle.md`,
`project_three_node_model.md`, `reference_wsl_vhdx_bloat.md`, and the `MEMORY.md` index.

## Risks

- **Ordering.** The tailscale rename (§2) kills MagicDNS `weasel` before eminix's ssh
  config is fixed (§3). Do §3 in the same sitting, or reach eminix by IP.
- **Session death.** Phase 4 ends this Claude session by design. Nothing may be left
  unpushed when it runs.
- **WT default profile.** Silent breakage, easy to mistake for "the rename broke WSL".
  Covered in §4.
- **Not a risk, stated to close the question:** ssh host key, tailnet IP, syncthing
  device IDs, agenix decryptability, and all listening ports are name-independent.
